# 页面可读性优化

用户反馈：页面内容看不清，截图显示文字偏小、灰色对比不足、中文夹杂大量终端式标签。

方案：保留两栏布局和现有查询行为，正文 16px、辅助信息至少 14px、标题 24–28px；浅色区域的正文使用 slate-800/900，辅助文字使用 slate-600；中文采用系统无衬线字体，SQL 与数值保留等宽排版。主要按钮至少 44px 高，历史显示两行，删除按钮与时间分开放置。

不采用整页 CSS 缩放：这会影响视口、滚动和手机适配；直接调整组件字号、间距和布局。

## 验证结果

- `pnpm lint` 与 `pnpm build` 通过；步骤名称一致性测试通过。
- Edge 验证正文、输入框、表格、SQL 为 16px，标题 24–28px，图表坐标 14px，主要按钮高度至少 44px。
- 首页、表格和 SQL 视图检查文字对比度：普通文字至少 4.5:1，大号标题至少 3:1；深色气泡辅助文字使用浅色以保持对比。
- 360/390/768/1024/1600px 无整页横向溢出，800×500 CSS 视口模拟放大后的布局重排，输入区仍可操作。
- 真实历史读取、柱状图、表格和 CSV 导出正常；SQL、折线图、复制状态、停止、失败提示、执行步骤展开/折叠用受控浏览器响应验证，未创建或删除真实历史。
- 截图已人工查看；首页与结果 PNG 已替换到 docs/images。详细对比与手机截图保存在 output/playwright/readability-*.png。
- 前后端在后台运行：前端 127.0.0.1:5174，后端 127.0.0.1:8001；启动输出保存在 logs/readability-*。

## 用户复核后调整

用户反馈 16px 太大，要求改为 14px：正文、输入框、历史、表格和 SQL 统一为 14px，区块标题为 16px，首页标题为 20–24px；保留深色文字和按钮点击面积。生产构建通过，浏览器确认正文/输入/历史/表格为 14px，1600px 桌面与 390px 手机无横向溢出。README 截图已更新。
